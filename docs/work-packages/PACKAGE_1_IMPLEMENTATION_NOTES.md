# חבילה 1 — הערות הטמעה ופריסה

## סדר פריסה בטוח

1. להריץ את migration `003_add_math_study_units.sql` על מסד הנתונים של הסביבה.
2. לפרוס Backend ולוודא ש־health check ונתיבי ההתקדמות מחזירים תשובה.
3. לפרוס Frontend ולבדוק מעבר פיזיקה → מתמטיקה → 3/4/5 יח״ל.

ה־migration תוספתי בלבד. הוא אינו מוחק מידע: נתוני פיזיקה נשארים במסלול כללי (`0`), ונתוני מתמטיקה קיימים משויכים ל־5 יח״ל, שהייתה ברירת המחדל לפני ההפרדה.

## Rollback

אם נדרשת חזרה לגרסה הקודמת, מחזירים את Backend ו־Frontend בלי להסיר את העמודות או האינדקסים החדשים. הגרסה הקודמת מתעלמת מהם, והמידע נשמר. אין לבצע `DROP COLUMN` בזמן אירוע Production.

## Studio

- חיבור SSE שולח heartbeat כל 10 שניות וזמן הפעולה המרבי הוא 170 שניות בשרת ו־180 שניות בדפדפן.
- טקסט שחולץ מקובצי Drive נשמר ב־`drive_text_cache` ומתחדש כאשר תאריך שינוי הקובץ משתנה.
- כשל זמני במטמון אינו מונע שימוש במקור עצמו.
- Studio משתמש ב־`AIGateway`. הגדרת הספק המוצפנת של המשתמש מקבלת עדיפות; מפתח ההדגמה הקיים משמש רק כתאימות לפריסה הנוכחית.

## בדיקות קבלה ידניות ב־Preview

- בחירת המקצוע והרמה נשמרת לאחר רענון ומשתקפת בסרגל העליון ובכל מודול.
- שיחה, העלאה, תרגול והתקדמות של 3 יח״ל אינם מופיעים ב־4 או 5 יח״ל.
- נוסחאות עם שברים, טריגונומטריה ונוסחה שנשברה בין שורות מוצגות ללא `$`, `\eq` או פקודות גולמיות.
- כשל של נתיב התקדמות אחד אינו מפיל את כל העמוד.
- ניסיון חוזר ב־Studio שומר את המקורות שנבחרו, והפעם השנייה משתמשת בטקסט שכבר חולץ.
- מסנני שם, מיקום, סוג קובץ וסטטוס עיבוד פועלים ומציגים מצב “לא נמצאו תוצאות”.

## המשך מתוכנן

מעבר למנגנון משימות מתמשך (queue/job ID) מתאים כאשר יהיו כמה משתמשים במקביל או מסמכים גדולים במיוחד. שכבת heartbeat והמטמון שנוספו בחבילה זו משפרים את היציבות כעת, בלי להכניס Redis/queue לפני שנדרש תפעולית.
